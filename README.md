# 📊 Broker Client — 多券商 K 線客戶端

統一接口取 / 流式接收多家券商嘅 K 線數據（目前：**富途 Futu** + **Interactive Brokers IB**），配 PySide6 GUI。所有 broker 一律回 `(status, data, message)` triple，失敗如實回報原因（無標的 / 無權限 / timeout 三句唔同）。

## ✨ 核心功能

- **統一 K 線契約**：`get_kline()` / `stream_kline()` 全部 broker 同一形狀；K 線 DataFrame schema 單一來源（`time_key, open, high, low, close, volume`），成功前自動驗證。
- **並發安全**：futu 所有 stream **共用一條** OpenD 連線（訂閱按 `(code, ktype)` refcount 增減，push 經單一 handler 路由落每條 stream 自己嘅 queue）；一次性 `get_kline` 照用獨立連線、用完即斷；IB 多 request 共用一條 TWS session、per-request error 歸屬（reqId scoping）— Run All 全矩陣可同時跑。
- **K 線切換週期加速 + 加載態 + 模組化共用**：五層一起做，冇一個係「調個參」可以解決嘅慢。① **程序層 K 線快取**（`modules/kline_cache.py`）— LRU 32 條 + TTL 按 ktype（分鐘 30s / 時鐘 120s / 日週月 600s），key `(code, ktype)`（唔理大細階），value 直接存 `set_bars` 形狀嘅 row tuple（**唔 store DataFrame** → 唔食 pandas 記憶體），只喺 GUI thread 用 → 唔使 lock；兩頁都讀寫 → **切返睇過嘅週期即刻上圖（0 ms，目標 <50 ms 已達標）**，真 baseline 到咗先覆蓋。② **兩段式取數**（`modules/futu_client.stream_kline` + config `futu.kline_num_first: 300`）— 第一段只取 300 根（同 `KlineChart.MAX_DRAW` 對齊）即刻上圖，背景先補取完整 `kline_num` 再 yield 一次快照 → 對 consumer 嚟講只係多一次 tick，**契約零改**，`MAX_VIEW` 嘅縮放深度亦唔減（呢個就係揀兩段式而唔係直接砍到 300 嘅原因）；順帶 futu 全部同步呼叫一律 `asyncio.to_thread` → 一格取數唔再拖慢其他格。③ **加載態收落 `KlineChart` 本身**（`gateway/ui/kline_overlay.ui` 惰性 `load_ui`）— `set_busy(True)` = 全圖加暗（`rgba` scrim，由 theme palette 現算，**唔使 `QGraphicsOpacityEffect`**：會 rasterize 成個 matplotlib canvas）+「LOADING」，8 秒後轉「仲喺度等」文案；因為寫喺 base class，**K 線頁 1 個圖 + 行情頁 6 格自動全有**，加載期間 pan/zoom 照樣郁到 canvas（`WA_TransparentForMouseEvents`），scrim 跟 theme、文案跟語言。④ **共用 OpenD 連線**（`modules/futu_client.py`）— 舊設計每條 stream / 每次 get 各開一條 `OpenQuoteContext`，行情頁 6 格 = **13 次 handshake 排喺同一個 event loop 前面**；而家全程序只開**一條**共享 ctx + 一個 `KlineRouter` handler，訂閱按 `(code, ktype)` **refcount** 增減（0→1 先真 `subscribe`、歸零先 `unsubscribe`），push 按 `(code, k_type)` 路由落**每條 stream 自己嘅 queue**（兩格設同一標的都唔會搶走對方嘅 push），收線由 `disconnect()` 負責（stream 結束只退訂閱、唔 close 共享連線）。🤖 實證：futu push 真的帶 `code`/`k_type` 欄，所以路由必須喺 `_normalize_kline` **之前**做（佢會 drop `code`）。失敗隔離：只有 transport 層異常先當連線死咗（權限／參數類 `RET_ERROR` 唔連累其他 live stream），下次取數自動重開。⚠️ 呢度改咗一段刻意寫低嘅設計，`futu_trade_page` 嘅 `_qctx` 屬另一條獨立連線，唔受影響。K 線頁 `ktype_combo` **即切**（串流期間照樣改到週期：`LoopThread.restart_stream` 一次過交俾 loop 做「先 cancel 舊、再起新」，被取代嗰次 run 嘅 `done` 會被壓住 → button 文案 / 輸入框狀態唔會被收復）。⑤ **stream 基建共用**（`gateway/kline_stream.py`）— 繪畫本来就只有一套（`KlineChart` + 唯一子类 `IndicatorKlineChart`），真正重覆咗兩份嘅係 **thread/worker 樣板**：`LoopThreadBase`（起 loop、喺自己條 thread 建 worker → signal 自動 queue 去 GUI、`worker_ready`、`request_shutdown` 2s deadline poll）＋ `ClientHolderMixin`（lazy 開 `BrokerClient`／`client_factory` 注入 fake、模板 `shutdown()` = cancel 自己啲 consumer task → `__aexit__` 釋放連線 → stop loop）。K 線頁 `Worker`/`LoopThread` 同行情頁 `GridWorker`/`_LoopThread` 一律變 subclass，page 檔得返自己嘅 facade。⚠️ **worker payload 形狀照樣各管各**（K 線頁 records / 行情頁 df）→ 用 mixin 而唔係共用 `QObject` base，兩頁 E2E 零改。⏳ `gui_fulltest.py` 仲有第三份複製未落返嚟（超出呢輪範圍）。
- **Symbol mapping L0–L4**：canonical = **Futu quote code**（用戶用 Futu app 對照）。L0 normalize → L1 config alias（IB-only pin）→ L2 per-client `resolve_symbol()`（IB 自動解析 front month，per-session cache）→ L3 broker 原生 fallback → L4 honest fail。永遠唔 hardcode 合約月份。
- **Error honesty**：IB errorEvent per-request capture + code→人話映射；「無標的 / 無 permission / timeout」如實分開講。

- **回測頁（`gateway/backtest.py` + `gateway/pages/backtest_page.py`）**：主菜單直按頁 — 標的（全域模糊輸入）／策略（`StrategyManager` 清單）／券商（`modules.registry.BROKERS`）／11 週期／根數 + **成本參數可調**（手续费%、滑價% 每邊、名義資金、無風險利率；範圍一律跟引擎 `clamp_*`，頁同 `.ui` 都唔 hardcode 數字）→ **非常詳細嘅「持倉表現」報告**。**計量口徑：唔准復利**（用戶明確要求「策略客觀每次嘅表現」）— 每筆**等額注碼**（固定名義 = 名義資金），淨值 = 初始資金 + Σ已平倉淨盈虧 + 未平倉 mark-to-market（**單利累加**），所有 % 分母恆定 → 每筆互相獨立、唔會因為早期贏蝕而失真；年化 = 總報酬% ÷ 年數（單利年化），年數優先由**真實時間軸**量度，時間軸不可用才退回 ktype 對照表（`meta.bpy_source` 如實標明 measured / ktype_table / default）。**持倉處理喺結果入面三處體現**：① 指標組「交易執行（持倉處理）」— 買/賣訊號數、**持倉中被忽略 / 空倉被忽略 / 價唔啱被忽略**計數、平均/最長持倉根數與日數、**喺市場時間覆蓋率**、**沽空時間覆蓋率**、未平倉數、**短倉筆數**、年換手、成本與滑價合計；② 交易明細表（**方向欄（多/空）**＋逐筆進出時間/價格/持倉根數/日數/毛%/成本%/淨%/P&L/**平倉原因**）；③ 被忽略訊號表（逐條時間/方向/價格/原因）。**持倉模式可揀（長倉 / 短倉 / 雙向）** — 選項、狀態機、忽略原因全部來自 `gateway/position_model.py`（同量化交易頁**同一份 enum、同一個 `step()`**，兩頁不可能講兩套口徑；默認長倉）：長倉＝空倉遇 B 開倉／持倉遇 S 全平；短倉＝鏡像（沽空）；雙向＝相反訊號即**反手 = 同一根先平後開兩筆**（成本四邊如實計、冇「平倉後變空倉」中間態），同向一律忽略（單倉唔加倉）；被忽略一律如實計數；樣本完結仍持倉 → 以最後收盤 MTM（`open=True`）。成交價 = 訊號根收盤（同 `strategies.trade_marks` 同一契約、冇未來函數）；沽空嗰邊報酬反號（價升 → 短倉虧）、滑價永遠朝唔利自己嗰邊。**62 個指標分四組**（`METRIC_DEFS` 單一來源：收益 18／風險 14／綜合風險回報 8／交易執行 22）— 總報酬/年化/勝率/獲利因子（盈虧比）/期望值/最佳最差筆/Buy&Hold 對照與超額；最大回撤與**最長回撤修復天數**/年化波動/下行波動/最大連續虧損/偏度峰度/VaR；夏普/索提諾/卡瑪/ recovery factor/貝塔/阿爾法/資訊比率 + Buy&Hold 夏普對照；執行與持倉。⚠️ 口徑分界如實：波動/夏普/貝塔用 **per-bar 報酬序列**（空倉根 = 0 → 「喐唔喐市場」照實），偏度/峰度/VaR 用**持倉中**嘅根（先至係「持倉時」嘅分布），覆蓋率另列，三者唔混淆；指標**暖機根數** `warmup_bars` 如實回報（前面冇訊號可能只係暖機，唔當「策略冇訊號」）。**覆核圖**：`EquityChart`（本檔自繪 QPainter，唔用 matplotlib → 零新依賴、唔同 K 圖搶記憶體）畫淨值 + Buy&Hold 對照 + 回撤帶，K 圖 B/S 覆核**直接重用** `indicators.IndicatorKlineChart.set_strategy` → 標記同回測用同一個 `trade_marks`，一致性屬結構保證（冇第二份訊號邏輯）；兩張圖跟 theme／語言，冇結果即如實收圖。取數經 `gateway/kline_stream` 共用基建，失敗如實三句唔同（攞 K 線失敗連 broker message／冇收到 K 線／回測本身出錯），每次執行派 token → 遲到結果一律作廢。本地記憶 = state_store section `backtest`。可單獨運行。
- **量化交易頁（`gateway/quant_exec.py` + `gateway/pages/quant_page.py`）**：主菜單直按頁 — 揀**策略 × 標的 × 週期 × 券商 × 交易環境 × 持倉模式**做「綁定」，用真策略訊號喺**即時**落單（唔係回測）。**全自動 ⇄ 半自動頁上有開關**（用戶原話）：全自動 = 訊號即行即落單、行風控；半自動 = 訊號連同「會做乜」（開/平/反手）入**待執行**清單，人確認先落單（人就係風控，唔行風控、唔推進持倉狀態）。**實盤 / 模擬都得、FUTU + IB 都得**：環境 = `trade_base.TRADE_ENVS`、券商 = `modules.registry.BROKERS`，**冇交易能力嘅券商唔靜默轉券商**（`trade_supported` 能力旗標如實擋）。**持倉模式同回測頁共用 `position_model`**（長倉/短倉/雙向，支援沽空）。**即時三道閘**（回測冇、即時必須有）：① baseline watermark — 訂閱時已存在嘅歷史訊號一律唔落單並如實計數；② 未收根過濾 — 只行動喺 `bar_idx ≤ n-2`（最後一根收盤價未定唔可以當成交價）；③ 去重 key `(綁定, bar_idx, side)` — 未行動嘅訊號留返下一輪，唔會漏亦唔會重覆落單。**風控最小三項全部可調**：最大同時持倉數／每日最大筆數／同一標的訊號冷卻根數（⚠️ `0` = 最嚴，唔係無上限；反手算 2 筆但唔增加持倉數）。**如實優先**：落單成功只係「已送出（未確認成交）」（`trade_base` 契約：兩家回執都唔帶成交與否，要睇 `open_orders`）；持倉表／訂單表直接讀券商帳戶（唔係本頁模擬）；落單失敗 → `requeue()` 還原持倉狀態（狀態同實際成交唔會脫節）；半自動確認時持倉若已中途變過 → 如實講「冇推進狀態」。**唔會自動開始監控**（真錢自動落單必須人明確撳一下），本地記憶只還原綁定／參數。口徑同源：訊號 = `strategies.trade_marks`、持倉 = `position_model.step` → 同回測用**完全同一個函數**，「回測表現」同「實際落單」唔會講兩套數；狀態全部住喺 worker thread（GUI 只 send 指令、收 snapshot／事件／券商資料），事件 key 語言中立 → 轉語言唔會令已寫低嘅日志變錯。可單獨運行。
- **券商交易能力契約（`modules/trade_base.py`）**：落單／訂單／持倉／資金嘅**單一介面**（獨立 mixin + `TRADE` 能力旗標，**唔改行情契約 `BrokerBase`** — 交易能力唔係每家都有）；回傳形狀同 `get_kline` 完全一致 `(status, data, message)`，失敗原因係券商原文；⚠️ 方法唔係 `@abstractmethod`（會即刻炸晒現有子類）→ 冇實作就喺**呼叫時**如實噴錯；帳戶/訂單/持倉/資金**欄位定義喺呢度**（`ACCOUNT/ORDER/POSITION/ACCOUNT_INFO_KEYS`）— 兩頁（FUTU 交易頁、量化交易頁）同兩家券商對同一個 dict 形狀，頁只揀邊幾欄顯示；`clamp_env` 統一清洗 REAL/SIMULATE（⚠️ 期間修真 bug：舊實作用 uppercase 查細階 alias 表 → 揀 REAL 永遠變 SIMULATE = 會錯錢）。預設交易券商喺 `modules/config.json` `source.trade`（同行情 `source.default` 分開）。
