# 📊 Broker Client — 多券商 K 線客戶端

以統一接口取得／流式接收多家券商的 K 線數據（目前：**富途 Futu** + **Interactive Brokers IB**），並提供 PySide6 GUI。所有 broker 一律回傳 `(status, data, message)` triple；失敗時如實回報原因（無標的／無權限／timeout 三者分開，不混為一談）。

## ✨ 核心功能

- **統一 K 線契約**：`get_kline()` / `stream_kline()` 全部 broker 同一形狀；K 線 DataFrame schema 單一來源（`time_key, open, high, low, close, volume`），成功前自動驗證。
- **並發安全**：futu 所有 stream **共用一條** OpenD 連線（訂閱按 `(code, ktype)` refcount 增減，push 經單一 handler 路由至每條 stream 各自的 queue）；一次性 `get_kline` 仍用獨立連線、用完即斷；IB 多個 request 共用一條 TWS session、per-request error 歸屬（reqId scoping）— Run All 全矩陣可同時執行。
- **K 線切換週期加速 + 加載態 + 模組化共用**：五層一併處理，沒有一層是「調個參數」可以解決的慢。① **程序層 K 線快取**（`modules/kline_cache.py`）— LRU 32 條 + TTL 按 ktype（分鐘 30s／時鐘 120s／日週月 600s），key `(code, ktype)`（不分大小寫），value 直接存 `set_bars` 形狀的 row tuple（**不存放 DataFrame** → 不佔 pandas 記憶體），只在 GUI thread 使用 → 不需 lock；兩頁共用讀寫 → **切回已看過的週期即刻上圖（0 ms，目標 <50 ms 已達標）**，真 baseline 到達後才覆蓋。② **兩段式取數**（`modules/futu_client.stream_kline` + config `futu.kline_num_first: 300`）— 第一段只取 300 根（與 `KlineChart.MAX_DRAW` 對齊）即刻上圖，背景再補取完整 `kline_num` 並 yield 一次快照 → 對 consumer 而言只是多一次 tick，**契約零改**，`MAX_VIEW` 的縮放深度亦不減少（這正是選擇兩段式而非直接砍至 300 的原因）；順帶 futu 全部同步呼叫一律 `asyncio.to_thread` → 一格取數不再拖慢其他格。③ **加載態收進 `KlineChart` 本身**（`gateway/ui/kline_overlay.ui` 惰性 `load_ui`）— `set_busy(True)` = 全圖加暗（`rgba` scrim，由 theme palette 即時計算，**不使用 `QGraphicsOpacityEffect`**：會 rasterize 整個 matplotlib canvas）+「LOADING」，8 秒後改為較慢的文案；因為寫在 base class，**K 線頁 1 個圖 + 行情頁 6 格自動全有**，加載期間 pan/zoom 仍可操作 canvas（`WA_TransparentForMouseEvents`），scrim 跟 theme、文案跟語言。④ **共用 OpenD 連線**（`modules/futu_client.py`）— 舊設計每條 stream／每次 get 各開一條 `OpenQuoteContext`，行情頁 6 格 = **13 次 handshake 排在同一個 event loop 前面**；現時全程序只開**一條**共享 ctx + 一個 `KlineRouter` handler，訂閱按 `(code, ktype)` **refcount** 增減（0→1 才真正 `subscribe`、歸零才 `unsubscribe`），push 按 `(code, k_type)` 路由至**每條 stream 各自的 queue**（兩格設同一標的也不會搶走對方的 push），收線由 `disconnect()` 負責（stream 結束只退訂閱、不 close 共享連線）。🤖 實證：futu push 確實帶 `code`／`k_type` 欄，因此路由必須在 `_normalize_kline` **之前**進行（該函數會 drop `code`）。失敗隔離：只有 transport 層異常才視作連線已死（權限／參數類 `RET_ERROR` 不連累其他 live stream），下次取數自動重開。⚠️ 此處修改了一段刻意寫下的設計，`futu_trade_page` 的 `_qctx` 屬另一條獨立連線，不受影響。K 線頁 `ktype_combo` **即切**（串流期間仍可更改週期：`LoopThread.restart_stream` 一次過交由 loop 執行「先 cancel 舊、再起新」，被取代那次 run 的 `done` 會被壓住 → button 文案／輸入框狀態不會被回收）。⑤ **stream 基建共用**（`gateway/kline_stream.py`）— 繪畫本來只有一套（`KlineChart` + 唯一子類 `IndicatorKlineChart`），真正重複了兩份的是 **thread/worker 樣板**：`LoopThreadBase`（起 loop、在自己執行緒建立 worker → signal 自動 queue 至 GUI、`worker_ready`、`request_shutdown` 2s deadline poll）＋ `ClientHolderMixin`（lazy 建立 `BrokerClient`／`client_factory` 注入 fake、模板 `shutdown()` = cancel 自己的 consumer task → `__aexit__` 釋放連線 → stop loop）。K 線頁 `Worker`/`LoopThread` 與行情頁 `GridWorker`/`_LoopThread` 一律改為 subclass，page 檔只餘下自己的 facade。⚠️ **worker payload 形狀仍各自管理**（K 線頁 records／行情頁 df）→ 使用 mixin 而非共用 `QObject` base，兩頁 E2E 零改。⏳ `gui_fulltest.py` 仍有第三份複製未合併（超出本輪範圍）。
- **Symbol mapping L0–L4**：canonical = **Futu quote code**（用戶以 Futu app 對照）。L0 normalize → L1 config alias（IB-only pin）→ L2 per-client `resolve_symbol()`（IB 自動解析 front month，per-session cache）→ L3 broker 原生 fallback → L4 honest fail。永遠不 hardcode 合約月份。
- **Error honesty**：IB errorEvent per-request capture + code→人話映射；「無標的／無 permission／timeout」如實分開回報。

- **回測頁（`gateway/backtest.py` + `gateway/pages/backtest_page.py`）**：主菜單直按頁 — 標的（全域模糊輸入）／策略（`StrategyManager` 清單）／券商（`modules.registry.BROKERS`）／11 週期／根數 + **成本參數可調**（手續費%、滑價% 每邊、名義資金、無風險利率；範圍一律依引擎 `clamp_*`，頁與 `.ui` 均不 hardcode 數字）→ **詳盡的「持倉表現」報告**。**計量口徑：不允許復利**（用戶明確要求「策略客觀每次的表現」）— 每筆**等額注碼**（固定名義 = 名義資金），淨值 = 初始資金 + Σ已平倉淨盈虧 + 未平倉 mark-to-market（**單利累加**），所有 % 分母恆定 → 每筆互相獨立，不會因早期盈虧而失真；年化 = 總報酬% ÷ 年數（單利年化），年數優先由**真實時間軸**量度，時間軸不可用才退回 ktype 對照表（`meta.bpy_source` 如實標明 measured / ktype_table / default）。**持倉處理在結果中三處體現**：① 指標組「交易執行（持倉處理）」— 買/賣訊號數、**持倉中被忽略／空倉被忽略／價不合適被忽略**計數、平均/最長持倉根數與日數、**在市場時間覆蓋率**、**沽空時間覆蓋率**、未平倉數、**短倉筆數**、年換手、成本與滑價合計；② 交易明細表（**方向欄（多/空）**＋逐筆進出時間/價格/持倉根數/日數/毛%/成本%/淨%/P&L/**平倉原因**）；③ 被忽略訊號表（逐條時間/方向/價格/原因）。**持倉模式可選（長倉／短倉／雙向）** — 選項、狀態機、忽略原因全部來自 `gateway/position_model.py`（與量化交易頁**同一份 enum、同一個 `step()`**，兩頁結構上不可能出現兩套口徑；默認長倉）：長倉＝空倉遇 B 開倉／持倉遇 S 全平；短倉＝鏡像（沽空）；雙向＝相反訊號即**反手 = 同一根先平後開兩筆**（成本四邊如實計，無「平倉後變空倉」中間態），同向一律忽略（單倉不加倉）；被忽略一律如實計數；樣本完結仍持倉 → 以最後收盤 MTM（`open=True`）。成交價 = 訊號根收盤（與 `strategies.trade_marks` 同一契約、無未來函數）；沽空側報酬反號（價升 → 短倉虧）、滑價永遠朝向不利自己的一方。**62 個指標分四組**（`METRIC_DEFS` 單一來源：收益 18／風險 14／綜合風險回報 8／交易執行 22）— 總報酬/年化/勝率/獲利因子（盈虧比）/期望值/最佳最差筆/Buy&Hold 對照與超額；最大回撤與**最長回撤修復天數**/年化波動/下行波動/最大連續虧損/偏度峰度/VaR；夏普/索提諾/卡瑪/recovery factor/貝塔/阿爾法/資訊比率 + Buy&Hold 夏普對照；執行與持倉。⚠️ 口徑分界如實：波動/夏普/貝塔使用 **per-bar 報酬序列**（空倉根 = 0 → 「市場有否波動」照實），偏度/峰度/VaR 使用**持倉中**的根（方為「持倉時」的分布），覆蓋率另列，三者不混淆；指標**暖機根數** `warmup_bars` 如實回報（前面無訊號可能只是暖機，不作「策略無訊號」解讀）。**覆核圖**：`EquityChart`（本檔自繪 QPainter，不用 matplotlib → 零新依賴、不與 K 圖爭記憶體）畫淨值 + Buy&Hold 對照 + 回撤帶，K 圖 B/S 覆核**直接重用** `indicators.IndicatorKlineChart.set_strategy` → 標記與回測使用同一個 `trade_marks`，一致性屬結構保證（無第二份訊號邏輯）；兩張圖跟 theme／語言，無結果即如實收圖。取數經 `gateway/kline_stream` 共用基建，失敗如實三者分開（取 K 線失敗連 broker message／未收到 K 線／回測本身錯誤），每次執行派 token → 遲到結果一律作廢。本地記憶 = state_store section `backtest`。可單獨運行。
- **量化交易頁（`gateway/quant_exec.py` + `gateway/pages/quant_page.py`）**：主菜單直按頁 — 選擇**策略 × 標的 × 週期 × 券商 × 交易環境 × 持倉模式**作為「綁定」，以真實策略訊號在**即時**下單（不是回測）。**全自動 ⇄ 半自動頁上有開關**（用戶原話）：全自動 = 訊號即行即下單、經風控；半自動 = 訊號連同「會做什麼」（開/平/反手）進入**待執行**清單，經人工確認後才下單（人即為風控，不走風控、不推進持倉狀態）。**實盤／模擬均可、FUTU + IB 均可**：環境 = `trade_base.TRADE_ENVS`、券商 = `modules.registry.BROKERS`，**無交易能力的券商不靜默更換券商**（`trade_supported` 能力旗標如實阻擋）。**持倉模式與回測頁共用 `position_model`**（長倉/短倉/雙向，支持沽空）。**即時三道閘**（回測沒有、即時必須有）：① baseline watermark — 訂閱時已存在的歷史訊號一律不下單並如實計數；② 未收根過濾 — 只行動於 `bar_idx ≤ n-2`（最後一根收盤價未定，不可作為成交價）；③ 去重 key `(綁定, bar_idx, side)` — 未行動的訊號保留至下一輪，不漏也不重複下單。**風控最小三項全部可調**：最大同時持倉數／每日最大筆數／同一標的訊號冷卻根數（⚠️ `0` = 最嚴格，不是無上限；反手計 2 筆但不增加持倉數）。**如實優先**：下單成功只代表「已送出（未確認成交）」（`trade_base` 契約：兩家回執均不帶成交與否，須看 `open_orders`）；持倉表／訂單表直接讀取券商帳戶（不是本頁模擬）；下單失敗 → `requeue()` 還原持倉狀態（狀態與實際成交不會脫節）；半自動確認時持倉若已中途改變 → 如實說明「未推進狀態」。**不會自動開始監控**（真錢自動下單必須人明確點擊），本地記憶只還原綁定／參數。口徑同源：訊號 = `strategies.trade_marks`、持倉 = `position_model.step` → 與回測使用**完全同一個函數**，「回測表現」與「實際下單」不會出現兩組數字；狀態全部位於 worker thread（GUI 只 send 指令、收取 snapshot／事件／券商資料），事件 key 語言中立 → 更換語言不會使已寫下的日誌變錯。可單獨運行。
